# 学习库（vault）：结构、状态机、看板与跨端续接

学习库是**用户自己的长期资产**：本地纯文本（Markdown + CSV + 可选 JSON），换任何 AI 工具都能接着用。
**不要把学习库推到公开仓库**，里面是个人学习与处境数据。

## 结构（三层 + 单页可视化看板）
```
vault/
├─ 00-我/                    # 个人模型，跨目标、长期复利
│  ├─ 画像.md                # 稳定层：长期方向、优势（附证据）、长期约束
│  ├─ 当前处境.md            # 状态层：阶段、目标、截止日期、每日可投入分钟、预算
│  ├─ 学习说明书.md          # 规则层：对本人真正有效的方法（每条必附证据），AI 开机必读
│  └─ 决策日志.md            # 路线拍板、换策略、止损的理由与结果对账
├─ 01-能力地图.md            # 已通过外部验证的能力存量，新目标诊断时直接跳过
├─ 02-目标/<日期_目标名>/    # 每个目标独立目录：计划.md、评价标准.md、诊断.md、课程包.json(互动课件)、岗位地图.json(可选)
├─ data/                     # 原始数据层：只追加，不篡改历史
│  ├─ attempts.csv           # 每次做题与任务尝试记录（含把握度与题目来源）
│  ├─ sessions.csv           # 每次学习时长与完成记录
│  └─ feedback.csv           # 外部验证记录（真题限时测、真人盲评、线上真实数据）
├─ notes/                    # 用户自己写的总结笔记（标注核实状态）
├─ library/                  # 可复用资产：评价标准、可信来源、经验库（固化跑通的拆解模板）
├─ 统计.md                   # 由 learn_stats.py 自动生成的统计报告（可随时重算）
└─ 看板.html                 # 由 learn_stats.py 自动生成的离线交互式可视化网页（桌面/手机通用）
```
**核心工程原则**：原始层（`data/`）只追加不修改；视图层（`统计.md`、`看板.html`）与结论层随时可由脚本从原始数据重新生成，骨架与数据彻底解耦。

## 节点五色证据状态机（严防"把 AI 测验通过当学会"）
路线图和看板中的每个能力/知识点条目严格区分**练习态**与**外部证据态**：
1. **⚪ 未开始（`todo`）**：尚无作答与练习记录。
2. **🟡 学习/练习中（`practicing`）**：已有练习记录，但近 3 次练习正确率 < 80% 或题量不足 2 题。
3. **🔵 练习达标·待外部验证（`ai_passed`）**：AI 出题或自练近 3 次平均得分 ≥ 80%，**但尚无外部验证证据——绝不标绿称"已学会"**，提醒尽快安排真题或真实交付验证。
4. **🟢 外部验证已掌握（`verified`）**：已在 `01-能力地图.md` 登记外部证据，或在 `data/feedback.csv` 判定达标，或 `attempts.csv` 中「真题 / 外部测验」样本 ≥ 2 题且得分率 ≥ 80%。
5. **🟠 到期复习 / 高估盲区（`due_or_blocked`）**：已到间隔复习日期，或出现"作答前把握度 ≥ 75% 但实际答错"的元认知高估盲区，优先排入今日复习。

## 文件格式规范

### data/attempts.csv（每道题或每次微任务一行）
| 列 | 填写说明 |
|---|---|
| 日期 | `2026-03-15` |
| 目标 | 目标文件夹名（如 `2026-03_短视频剪辑`） |
| 条目 | 阶段 1 拆出的条目名（知识点 / 子技能 / 工作任务） |
| 题目 | 简述题目或任务动作 |
| 作答 | 用户的原始作答关键过程（保留思路，不只是 A/B/C/D） |
| 结果 | `对` / `错` / `部分`（或 `0`–`1` 之间的小数） |
| 把握度 | 作答**之前**报的 `0`–`100` 整数 |
| 用时秒 | 可空 |
| 错因 | `概念不懂` / `步骤错` / `没读清题` / `粗心` / `会但说不清` / `迁移失败`（全对留空） |
| 题目来源 | `AI出题` / `真题` / `外部测验`（**区分练习与真凭实据的关键列**） |

### data/sessions.csv
`日期,目标,模式,分钟,完成内容,状态(1-5),备注`

### data/feedback.csv（外部验证台账）
`日期,目标,验证方式,评价人或来源,结果,证据链接,结论`
（注：`结论` 列填写 `达标` 或 `未达标`；填 `达标` 且关联目标或条目时，看板会据此点亮对应证据状态。）

### 02-目标/<日期_目标名>/岗位地图.json（可选，求职/入职/实战技能拆解用）
用于把"岗位要求 → 具体任务动作链 → 输入/产出物 → 对接角色 → 所需能力与工具"连成可视化网状/链路地图。**骨架固定，换任何岗位只需替换此 JSON 数据文件**；未采集真实招聘样本时，`sample_count` 与薪资区间必须留 `null` 且 `is_verified_sample` 设为 `false`，严禁伪造样本：
```json
{
  "role_name": "目标岗位或技能方向名称",
  "industry_city_level": "行业 / 城市 / 级别（未定填空）",
  "sample_count": null,
  "collected_at": "",
  "is_verified_sample": false,
  "salary_range_k": { "low": null, "mid": null, "high": null },
  "summary": "一句话说明该岗位的核心价值与交付主线",
  "modules": [
    {
      "name": "核心职能模块名",
      "tasks": [
        {
          "name": "具体工作任务名",
          "weight": 8,
          "frequency": "高频/日常",
          "chain": ["01 第一步动作与标准", "02 第二步动作与避坑点", "03 第三步验收动作"],
          "input": "接收什么原始材料或需求",
          "output": "交付什么可验收产出物",
          "collaborators": "独立完成 / 对接哪些上下游角色",
          "skills": ["关联阶段1的条目名"],
          "tools": ["常用标准工具名"]
        }
      ]
    }
  ]
}
```

### 02-目标/<日期_目标名>/课程包.json（网页内免打字互动学习课件）
用于驱动 `看板.html` 内的互动学习舱（点开任意路线节点即可直接在网页内「看正反例精讲 → 点开引导追问 → 点选选项当场判卷看解析 → 自动更新节点颜色」）：
```json
{
  "条目名称": {
    "why": "一句话说明为什么必须学这一站（对应什么真实任务或考点）",
    "core_points": ["核心判断法则 1", "核心判断法则 2"],
    "good_case": "达标正例（具体可见的做法与效果）",
    "bad_case": "新手翻车反例（最常踩的坑及后果）",
    "guided_qa": [
      { "q": "新手不知道该问的关键边界问题？", "a": "良师直接给出的清晰解答与证据依据" }
    ],
    "quizzes": [
      {
        "type": "practice",
        "stem": "情景题干（如试标判例或概念辨析）",
        "options": ["A. 选项一", "B. 选项二", "C. 选项三", "D. 选项四"],
        "answer": 0,
        "explain": "答完当场展示的解析：为什么该项对、其余项错在哪"
      }
    ]
  }
}
```
（注：`quizzes[].type` 填 `"practice"` 表示 AI 练习题［全对封顶升为 `🔵 练习达标·待外验`］；填 `"heldout"` 表示基于真实真题/行业试标原题改编的留出检验题［通过后可点亮 `🟢 外部已验证`］。）

### 学习说明书.md 的规则格式
```
- 规则：先走通一个最小成品闭环，再回头补单点概念
  证据：第 2 周对比，留出实操题完成率从 40% 升至 80%（data/attempts.csv）
  日期：2026-03-10　复验日期：2026-06-10
```
没有数据支撑的个人偏好只能写在"未验证的偏好"下，不能当正式规则锁定。

## 可视化看板与跨端（电脑 ↔ 手机）续接
1. **一键生成看板**：运行 `python scripts/learn_stats.py vault`（或 `python scripts/learn_stats.py board vault`），无需联网和第三方包，直接生成单文件 `vault/看板.html`。
2. **电脑与手机无缝衔接**：
   - 在电脑端：浏览器打开 `vault/看板.html` 查看时间对账、点选路线图节点、查看岗位任务链与上下游交付物、核对每周复盘雷达。
   - 离开电脑在手机端：可直接把 `看板.html` 发到手机浏览器离线打开做到期自测（做完点"复制新增 CSV 记录"），或在任意手机聊天框使用 **D-Lite 碎片模式**（5–10 分钟快测），回电脑后把生成的 CSV 行粘贴回 `data/attempts.csv` 重跑脚本即可同步全部进度。

## 复盘与阶段转换节奏
| 时机 | 动作 |
|---|---|
| 每次开始 | 读学习说明书、当前处境、计划、到期复习与高估盲区，一句话明确今日目标 |
| 每次结束 | 追加 `attempts.csv` 与 `sessions.csv`（不在电脑前则输出可复制 CSV 块） |
| 每周复盘 | 运行 `learn_stats.py` 更新 `统计.md` 与 `看板.html`；按"完成了什么 / 卡在哪 / 下周改哪一步"复盘并核对止损线；提议更新学习说明书 |
| 每月复验 | 做一次隔月延迟留出测验；清理未核实废笔记；复验到期规则 |
| 阶段里程碑 | 复盘得失写入决策日志 → 把有外部证据的条目晋升进 `01-能力地图.md` → 3 问更新当前处境 → 给出下一阶段 2–3 个方向选项由用户拍板 → 把跑通的调研/学习工作流沉淀进 `library/经验库.md` |
