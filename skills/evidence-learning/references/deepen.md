# 深化：把任务做深，而不是做大

## 输入（缺了就问）
- **要做**：一句话说任务
- **用途**：给谁用、用来干什么、**做成什么样算成功**
- **条件**：时间、预算、会用的工具、手上已有的材料
- **原来的提示词**（没有就写"无"）

**先别执行任务本身。**

## 步骤
0. **先判断**：缺少哪些会明显改变结果的信息？有就先问，最多 3 个问题，等回答后再继续。如果原提示词已经够好，直接说，不要硬改。
1. **专家多做的事**：这个领域的顶尖专家会多做哪些用户没要求的？只挑对【用途】影响最大的 3 件，按「效果大、代价小」排序，每件写一句代价。
2. **新手的错**：最常犯的 3 个错误，每个写一句怎么防。
3. **原始材料**：专家用哪些第一手数据或原始出处？从哪里能拿到？优先用用户手上已有的材料。
4. **方法和工具**：写标准名称（中英文都写），方便用户自己去搜。
5. **验收标准**：外行能逐条打勾或去外部查证的标准，分两类：
   - **A. AI 能自己检查的**
   - **B. 必须由用户或外部验证的**（真人反馈、平台数据、官方文件、实际测试）。AI 自评不能代替这一类。

第 3、4、5 步的每一项都标「确定」或「不太确定」；不太确定的写明怎么核实，**不要编**。

## 输出
1. 第 0–5 步的回答。用表格写，保持简短。
2. **改写后的提示词**：
   - 只加对结果影响最大的内容（来自第 1、2、5 步），每处新增后面用（←第 X 步）标出来源
   - 长度**不超过原提示词的 1.5 倍**（原来没有提示词的，控制在 25 行以内）；原来有效的部分保留原话
   - 末尾要求：交付前按第 5 步逐项自检，**A 类列出通过 / 未通过，B 类列出需要用户去验证的清单**
3. **一条可存档的经验**：下次同类任务能直接复用的一句话。存在学习库的话，追加到 `vault/library/经验库.md`。
